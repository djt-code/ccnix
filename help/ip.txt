ip: set up and look at the network (lib/net.lua)

  ip
      the interfaces, routes and whether it's up
  ip up | ip down
      start or stop the network on this computer
  ip boot [off]
      start it at every boot: the setting net.boot, which startup goes by (setup's net and router apps turn it on)
  ip link
      the modems there are, their MACs, and which are set up
  ip addr
      the interfaces' addresses and counts (-d: their MACs too)
  ip addr add <iface> <addr/len>
      give an interface an address
  ip addr del <iface>
  ip route
      the routing table
  ip route add <net/len|default> via <gw> [dev <iface>]
  ip route del <net/len|default>
  ip route get <addr> [dev <iface>]
      the way a packet to addr would go: the next hop (via), interface, source address, the route that picked them, and what ARP knows of the next hop
  ip neigh
      the ARP cache: addresses, their MACs and the seconds each is kept for yet (permanent: set by hand); and those being asked for, not yet answered (INCOMPLETE), with the packets waiting
  ip neigh add <addr> lladdr <mac> [dev <iface>]
      a permanent entry: addr is at mac (never asked for, never expires, not changed by what ARP hears); dev: the interface, if not the one whose network addr is on
  ip neigh del <addr> [dev <iface>]
      forget addr's entry, permanent or learned
  ip forward [on|off]
      route between interfaces (a router)
  ip rpfilter [strict|loose|off]
      which sources a router passes on (BCP 38): loose (the default) any it has a route back to, strict only those whose route back leaves by the interface the packet came in on, off all.  A packet from a source that can't be (0.x, 127.x, 224.x and up, the network's broadcast address, this computer's own) is dropped whatever it's set to.  On a router whose default route covers everything, loose stops only those: strict is the one that keeps a network's hosts from forging another's addresses
  ip host [<name> <addr>]
      names for addresses (ping router)
  ip dns [<primary> [<secondary>] | off]
      the DNS servers names are looked up at after the hosts (lib/netdb); none: the hosts alone
  ip dns cache
      the answers kept (each name's, "no such name" too, for the seconds its TTL says) and the servers asked last for now, having failed
  ip dns flush
      forget them all: the next lookup asks
  ip help
      the commands, and how short each may be

Words may be shortened, as iproute2's may, as far as they stay clear: `ip a` is ip address, `ip r a 10.0.3.0/24 v 10.0.1.1` ip route add ... via, `ip n` ip neighbour, `ip rp strict` ip rpfilter; `ip help` shows how short each command may be.  One too short to tell apart (`ip d`: down or dns?) is refused, with what it could be.

Options go before the command: -d (-details, or any cut between) adds the details, as iproute2's does: the MACs in `ip -d addr` and plain `ip`.

An interface is a modem by its peripheral name ("back", "modem_0"), or a VLAN on one: "back.20" is VLAN 20 on the back modem, its own network on the same wire.  What's set is kept in settings (net.if.<iface>, net.routes, net.neigh, net.forward, net.rpfilter, net.hosts, net.dns) and applies at once if the network is up.  The network runs alongside everything else once `ip up` has started it: see lib/net.lua.  `help network` walks through setting up two networks and a router.
