setup: ccnix on a turtle or computer: put it there, choose what it runs, update it

  wget run https://raw.githubusercontent.com/djt-code/ccnix/main/deploy/setup.lua [app...] [options]
  ccnix setup [app...] [options]       (once ccnix is there)

Apps (any number; none means everything for this kind of device):
  mine farm mow autocompost claude
      turtle programs (with turtlelib, home and autostart)
  coreutils
      cat, grep, ls-style utilities...
  ccsh
      the POSIX-style shell, started at boot
  diskclone
      for a computer with a disk drive
  fileserver
      its disk drives as one folder, /jbod
  net
      the network: ip, ping, traceroute, nc, host, netstat, tcpdump, curl; up at every boot
  router
      the network, and routing between networks: forwarding on, up at boot
  init
      processes and services: init at boot, ps, kill, service; the system log (syslogd as a service, logger)
  telnet
      the telnet client, and the network
  telnetd
      the telnet server as a service, with init and the network (then set telnetd.password)
  httpd
      the web server as a service, with init and the network: serves /www, Lua pages in /www/cgi
  irc
      the IRC client, and the network
  ircd
      the IRC server as a service, with init and the network: NickServ, ChanServ, #minecraft (`help ircd`)
  screen
      windows that stay when you detach (or telnet drops): screen -r; with init
git and deploy/ always come; so do the help files of what you pick.

Options: --autostart <app> (a turtle runs it at every boot: resumes its job, or starts one from the settings; see turtle/autostart.lua; on a computer: router, its status screen at every boot), --example (httpd, and a guestbook in its script root: /cgi/guestbook), --ccsh, --net, --router, --init (what ccsh, net, router and init set, without naming them), --no-reboot, --all (everything, sim/ too), --skip <dir> (leave out more).

  setup mine --autostart mine
      a miner that carries on after reboots
  setup farm coreutils ccsh
      a farmer you can also use as a shell
  setup router --autostart router
      a router, its screen up at boot

There are two ways ccnix runs, and setup does what each needs:

 * On a server with the ccnix mod, every program is in the ROM (/rom/ccnix) and the ROM's autorun runs deploy/boot.lua at every boot: nothing to clone.  setup moves an install from before ccnix over (/cc-turtles: its startup lines and files go; a turtle's job files move the first time they're used), brings this computer's updates up to date (ccnix update), and sets the settings the apps want.
 * On a server without it (stock CC: Tweaked), setup fetches the latest git, clones the repo into /ccnix, or pulls it if it's there (an install at /cc-turtles, the folder until 2026-10-29, is moved there first, and its saved remote, the repo's name before it was ccnix, is pointed at ccnix), sets the settings, and writes two lines into the computer's startup that run deploy/boot.lua from the checkout: `boot.lua` at the top of /startup.lua, `boot.lua --end` at the bottom (or, with a /startup folder, /startup/00-ccnix.lua and zz-ccnix.lua, which run first and last).  Lines an earlier install wrote (any naming the checkout, or /cc-turtles) and its old startup files go; your own lines stay.  A clone leaves out what the device doesn't run (sim/, and pc/ on a turtle or turtle/ on a computer): see bin/git.lua.  With HTTP off on the server, a checkout put there by hand (in /ccnix, or wherever this setup.lua runs from) is set up as it is.

Then it reboots (--no-reboot: from a checkout, boot runs in this shell instead).  Run it again any time: naming apps again changes what's there, naming none keeps the choice; `ccnix update` updates either way.  It's also the way out of a clone that filled the disk part way: what that left in the folders a clone leaves out, and Lua files in the top folder from before bin/ and turtle/, are deleted; the rest is kept and finished.  git runs from memory, so a full disk is no bar to starting.  An old bootstrap copy of git at /git.lua is removed, since the repo has its own in bin/.

deploy/boot.lua is apart from this on purpose: it runs at every boot (from the ROM's autorun, or from the startup lines this writes) and says what startup does; setup runs once, to put things in place.
