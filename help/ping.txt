ping: send ICMP echo requests and time the replies

  ping [-q] [-c count] [-i seconds] [-t ttl] [-W seconds] [-w deadline] [-s size] [-I iface|addr] host

host is an address (10.0.2.5) or a name: lib/netdb looks it up (`ip host`'s names, then DNS: `ip dns`).  Sends echo requests `-i` (1) seconds apart, each waiting up to `-W` (2) seconds for its reply, and says what came back: a reply (its TTL, and the round trip in milliseconds), "destination unreachable" from a router or this computer (no route: net; no ARP answer: host), "administratively prohibited" (a filter: a Network Gateway in NAT mode carries no ICMP past it, though it answers ping itself), or time exceeded (the TTL ran out on the way: a routing loop, or -t too small).

It goes on until Ctrl+T, or until `-c` requests have gone (-c 0: no limit), then says how many went and came back, and the round trips' least, mean and most, and their standard deviation (min/avg/max/mdev). -w stops it after deadline seconds, however many have gone; with -c too, it stops as soon as count replies are in.  -q prints only the first line and the summary.

-s puts size bytes of data in each request (0 to 65507; none unless given): the far side sends them back, so each reply shows its size (bytes=), and one that comes back short or changed says so.  Large ones test a path's limits (the ccnix mod's gateway carries the data as a real ICMP payload).

-I sends from an interface ("back.20": its address, and out of it only, whatever the routes would otherwise pick) or from one of this computer's addresses (the routes pick the way, as ever).  The answer comes back to that address, so it shows whether the far side can reach it. Exit status 0 if any reply came (with -w and -c: if count came), 1 if not, 2 for trouble (the network isn't up, a name that can't be looked up).
