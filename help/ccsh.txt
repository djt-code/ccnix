ccsh: ccsh, a small POSIX-style shell for CraftOS

  ccsh
      an interactive shell
  ccsh -c 'commands' [name [arg...]]
      run one command line
  ccsh script [arg...]
      run a file of commands

ccsh runs inside the stock CraftOS shell and has it find and run the programs (the same path, aliases and directory; cd, alias and set work as they always do).  What it adds:

  a | b | c
      pipes.  Each command runs to its end, then the next reads what it wrote: nothing streams, so `a | head` still runs all of a.
  < f   > f   >> f
      redirects; also 2> f, 2>> f, 2>&1, >&2, n>&-, and &> f (output and errors to f), &>> f. /dev/null works for reading and writing.
  a ; b   a && b   a || b   ! a
      and a newline is a ;
  'single' "double" \x
      quoting; # starts a comment.  A line ending in \, |, &&, || or inside quotes goes on to the next.
  X=value $X ${X} $? $#
      $1..$9 ${10} $@ "$@" $* $$ $PPID $! $0 variables.  $PATH is the shell's path (setting it changes the path), $PWD its directory and $HOSTNAME the computer's label (its ID if it has none).  $! is the last & job's process ID. $$ is the shell's (under init; else the computer's ID), $PPID its parent's.
  ${X:-word}
      word if X is unset or empty; ${X:=word} that, and X set to it; ${X:+word} word if X is set and not empty, else nothing; ${X:?word} if X is unset or empty, an error (word the message) and a script ends.  Without the colon (${X-word}), only unset counts.  The word is expanded: ${X:-$HOME}.
  export X  X=1 cmd
      the environment.  Programs read it with os.getenv("X") (and change their own copy with os.setenv(name, value), list it with os.environ()): the exported variables (PS1 is one), PATH, PWD and HOSTNAME, and for one command its own X=1 words.  A ccsh run from ccsh starts with them as exported variables; `env` shows them.
  PS1
      the prompt, an exported variable: \h (label, or ID), \w (the directory), \W (its last part), \i (the ID), \$, \n and \\: PS1='\h \W\$ '.  It starts as '\h:\w\$ ' ("label:/dir$ ") on a computer with a label, '\w\$ ' without one, unless the environment brought one.
  *  ?  [abc]  [!a-z]
      globs; a name starting with a dot only matches an explicit dot, and the fileserver's member disks (/disk, /disk2... with /jbod mounted) only a pattern that starts with a plain character (disk*, not *). No match leaves the word as is.
  $(cmd)  `cmd`
      command substitution (in a subshell).
  if a; then b; elif c;
      then d; else e; fi
  while a; do b; done
      until a; do b; done
  for x in words; do b; done
      (no `in words`: "$@")
  case word in pat|pat) a;; (pat) b;; *) c;; esac
      (globs, as in names)
  { a; b; }
      a group; ( a; b ) a subshell: its variables, functions, exit and directory are its own
  name() { body; }
      a function (function name { body; } too): $1... are its arguments; return [n]; local name[=value] until it returns
  break [n], continue [n] out of, or on round, the n'th loop out.
      Any of these can be piped and redirected as a whole: for f in *; do ...; done | sort, while read l; do ...; done < file.  They span lines at the prompt.  A loop lets the rest of the computer run every 100 turns, and Ctrl+T stops it.
  a &
      a background job: the line goes on while it runs.  It gets its own copy of the variables and every event but the keyboard's and the mouse's.  At the prompt, Ctrl+Z stops the job in front (a stopped job keeps the events it misses for later).  Under init, see below.
  jobs [-l|-p]          the jobs: [1]+ Running
      sleep 10 &
  fg [%n]  bg [%n]
      a job to the front (waiting for it), or a stopped one carried on in the background.  %n is job n; %% or %+ the latest, %- the one before, %str the one whose line starts so.
  fg prog  bg prog
      as CraftOS's fg and bg: prog in a new multishell tab (shown, for fg), with the environment.
  wait [%n|pid...]
      wait for jobs (all, with none named); their status.  Ctrl+T stops waiting.
  kill [-9] %n|pid...
      end a job as Ctrl+T would; -9 drops it at once, -STOP stops it, -CONT carries it on.  Under init, a pid that isn't a job's is a process's (see ps), and -pid a process group's.
  builtins
      also exit [n], :, true, false, read [-r] name..., shift [n], unset [-v] name... (variables), unset -f name... (functions), . file, export [-n] name[=value]... and export -p, [ expression ] (test, with a last ])

Not yet: here-documents, $(( arithmetic )) (expr does sums), ~.

At the prompt, ccsh first runs the commands in /.profile (PS1, export...), as `. /.profile` would.  Tab completes a program's name, and an argument as the stock shell would, or else as a file or directory name: what it would add shows in grey after the cursor.  The up and down keys go through the lines typed before, kept in $HISTFILE (/.ccsh_history; unset or empty, none) across sessions and tabs, the last $HISTSIZE of them (1000; 0 keeps none).  Both are shell variables, set before /.profile runs so it can change them.  The line is edited with a Unix shell's keys (lib/readline; the read builtin's too, at the keyboard):

  Ctrl+A, Ctrl+E, Home, End
      the start / the end of the line
  Ctrl+B, Ctrl+F, Left, Right
      a character back / forward
  Alt+B, Alt+F
      a word back / forward (or Esc then b/f)
  Backspace, Delete, Ctrl+D
      a character out (before / under it)
  Ctrl+K, Ctrl+U
      cut to the end / to the start
  Ctrl+W, Alt+Backspace, Alt+D
      cut the word before / before / after
  Ctrl+Y
      put back what was cut last
  Up, Down, Ctrl+P, Ctrl+N
      the history (Up and Down go through the completions while one shows)
  Ctrl+R
      search back through the history as you type: Ctrl+R again for an older match, Enter runs it, Ctrl+G gives up, another key edits it
  Tab
      the completion shown
  Ctrl+L
      clear the screen
  Ctrl+C
      drop the line (status 130)
  Ctrl+D on an empty line
      leave, as exit does

A long line scrolls sideways.  Tap Ctrl+R: held, CraftOS reboots (and Ctrl+S held shuts down).  Leave with exit, Ctrl+D, or by holding Ctrl+T at the prompt; with jobs left, the first try only warns, and the jobs end with the shell.  Ctrl+C or Ctrl+T while a command runs stops it, and the rest of the line, with status 130.  Programs that use Ctrl+C as a key get it as a key instead: CraftOS's edit (so nano), paint, lua, shell, multishell and games, which Ctrl+T still stops, and ccnix's vi, vim and telnet (and, under init, any program that ignores INT).  A script or -c waits for its background jobs before it ends: they can't outlive it.

Under init (`help init`), a program from the path runs as a process of its own, as Unix's shells fork one: a child of this shell's, which ps lists and kill and Ctrl+T reach.  At the prompt each job is a process group (its number is $! and what jobs -l shows), put in front of the terminal while it's the job in front, so the keyboard goes to it, and Ctrl+Z stops the whole group, and the job; Ctrl+C sends the group INT, which ends it as Ctrl+T would, but for a program that ignores INT (proc.ignore: vi, telnet), which gets the key.  Builtins, functions and compound commands run in the shell itself (cd and X=1 have to).  A script or -c runs its programs in its own group, so Ctrl+T reaches it and them alike.

A script can start with #!/ccnix/bin/ccsh (the stock shell honours the #! line; under the ROM alone it's #!/rom/ccnix/bin/ccsh), or run as `ccsh script`.

Programs see a pipe or a file as io.input() and io.output().  print, write, term.write and printError are redirected too, so stock programs can be piped: `ls | grep lua`.  ls lays its names out in columns as it would on screen, so `ls | wc -l` counts rows, not files.  Full-screen programs (edit, paint) need the screen: don't pipe them.  While a command runs, _G.POSIX_SH is set (echo leaves > to the shell then).
