telnet: a telnet client: another computer's shell or screen, here

  telnet host [port]
      (port 23, telnet)

host is an address or a name (lib/netdb: `ip host`, then DNS); port a number or a service's name.  Connects over the network stack (`ip up`) and shows the other side's screen: telnetd on another computer (a shell, or its console), or any Telnet server that draws with ANSI escapes.  What you type goes there, arrows and all; the mouse and pasting too, if the server asks.  A server that echoes (telnetd, most) gets each key as it's typed; one that doesn't (a MUD, nc) gets a line at a time, edited here (Backspace) and sent at Enter, as BSD's telnet does.  Enter is sent as CR LF.  Ctrl+T goes there as Ctrl+T, and under init Ctrl+Z goes there too (it stops what runs over there, as in a raw-mode terminal).  Ctrl+] is telnet's own: then q leaves, t sends an "interrupt process" (what stops a program even on the console), z stops telnet itself here (a job: fg brings it back), any other key goes back.  It ends when the other side closes.  A screen without colour shows the colours as greys.
