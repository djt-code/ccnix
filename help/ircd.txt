ircd: an IRC server, with services and a bridge to the game's chat

  ircd [-p port]
      serve IRC until Ctrl+T

A small IRC server in the manner of ngIRCd: one server (no links to others), the commands clients use (lib/ircd: NICK, JOIN, PRIVMSG, MODE, TOPIC, KICK, WHOIS, WHO, LIST, AWAY, OPER...), channels with their operators, bans, keys and limits.  Any IRC client works: irc here, or HexChat or irssi on a real machine through the ccnix mod's gateway.

Services come with it (lib/ircserv), as users:
  NickServ
      REGISTER, IDENTIFY, GHOST... keeps nicks for their owners; VERIFY <player> ties a nick to a Minecraft player (a code whispered in the game, CONFIRM <code> in IRC)
  ChanServ
      REGISTER #chan keeps a channel's founder, topic and auto-ops (OP, DEOP, AOP)
  MC
      the game: PLAYERS, TIME, WEATHER, TELL <player> <text>
MC sits in the bridge channel, #minecraft: what's said there goes into the game's chat, and the game's chat (and joins, leaves, deaths) comes back.  It uses what's attached to this computer: an Advanced Peripherals Chat Box (chat both ways), Player Detector (who's on, joins and leaves) and Environment Detector (weather); a command computer can speak and list players without them.  The world's clock needs nothing.

As a service (init keeps it running, and starts it again if it ends):
  setup ircd                      all of it at once: the files, the network
                                  and init at boot, the service enabled
or by hand:
  service add ircd ircd
      the service (-p port can follow)
  service enable ircd
      started at every boot
  service start ircd
      started now
  service status ircd
      running?  its last lines, how it last ended
  service stop ircd
      stopped (QUIT to everyone: "Server shutting down")
  service disable ircd
      not at boot any more
  service remove ircd
      gone (its settings and data stay)
Its log is the system log's (`help syslog`): connections, operators, what it found to talk to the game with, under the name ircd.  Change a setting with sysctl, then `service restart ircd`:
  sysctl ircd.oper=hunter2
      an operator password
  sysctl ircd.bridge=
      no bridge channel
  sysctl ircd.name=irc.lab
      the server's name

Settings, which -p overrides:
  ircd.port
      the TCP port (6667)
  ircd.name
      the server's name (irc.<this computer's label>, or irc.ccnix)
  ircd.network
      the network's name (ccnix)
  ircd.motd
      the message of the day, a file (/etc/ircd.motd)
  ircd.password
      a password every client must give (PASS); unset: none
  ircd.oper
      OPER's password (OPER <any name> <password>); unset: no operators
  ircd.bridge
      the channel bridged to the game's chat (#minecraft; "" for none)
  ircd.data
      where the services keep nicks and channels (/etc/ircd.db)
  ircd.facility
      the system log's facility (daemon; `help syslog`)

The message of the day is the file, a line each; edit it and restart. The services' data is textutils.serialize'd; deleting the file forgets every registered nick and channel.

It needs the network (`ip up`).  Then `irc <this computer>` from any computer on the network (`ip host irc 10.1.1.5` gives it a name), or from a real machine through the gateway.  Run in the foreground (just `ircd`), it logs to the screen too, and Ctrl+T stops it.
