init: processes and services: the first process

  init
      take over this computer: services, then the console
  init boot [off]
      run it at every boot (or not): the setting init.boot

CraftOS has no processes or background programs (only multishell's tabs, on advanced computers).  init is the nearest thing to Unix's: it runs every program as a process with a process ID, its own terminal and its own environment (see lib/proc.lua), and keeps services running in the background.  `ps` lists the processes, `kill` signals them and `service` starts, stops and sets up services.

At boot (init.boot on: `ccnix setup init`) startup runs init last. It starts the services that are enabled, then the console: the autostart (ccnix.autostart: the miner, farmer, router...) if one is set, then ccsh if ccsh.login is on, then the CraftOS shell; each when the one before it ends.  Leaving that last shell shuts the computer down, as leaving CraftOS's own does.  Run by hand, init skips the autostart.  A turtle's job that's a service of the same name (service.mine..., which setup sets up with init) runs as that instead, in the background, and the console starts at ccsh or the shell.

What a service prints is logged too, a line each under its name (printError's at err), and so is each service starting, ending and failing: syslogd, a service of its own, files it (`help syslog`). service.<name>.log false leaves a service's output out.

The keyboard and mouse go to the console: to the process group in front of it (ccsh puts each job there in turn; Ctrl+Z stops it, Ctrl+C ends it); every other event to every process.  The console keeps a scrollback, as a Linux console does: Shift+Page Up and Down look back through what scrolled off its top (the last 500 lines); any other key comes back.  A program that computes for a long time without waiting holds everything up, as it does in CraftOS.

A program that crashes ends its own process alone, failed (status 1 unless it gave one): the error and its traceback go to the log, and `service status` shows a service's.  When a process ends, the sockets it had open are closed (its ports free again).

A panic: if init itself fails (a bug in it, not in a program), it writes what it knew to /var/log/panic (the error and where, the processes, the log's messages not yet filed), then reboots after init.panic seconds (10 unless set; holding Ctrl+T meanwhile shuts the computer down instead; 0: no wait, it shuts down at once, as it did before).  The next boot logs the panic at crit and moves the report to /var/log/panic.1.
