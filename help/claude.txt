claude: let Claude drive the turtle

Talks to the Claude API (Anthropic) from the turtle over HTTP and gives the model one tool that matters: `lua`, which runs the Lua it writes on the turtle, with the turtle API and turtlelib (T) in scope.  You give it a goal; it works at it, call by call, says what it did, and asks when it isn't sure.

Usage:
  claude [goal words...] [--model id] [--effort low|medium|high]
         [--steps N] [--cache 5m|1h] [--confirm] [--resume]

  claude dig a 3 by 3 tunnel 20 blocks ahead and come back
  claude                      asks for the goal

  --model id
      the model: opus, sonnet or haiku (claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5), or any model id as the API names it (default opus)
  --steps N
      at most N tool calls per goal (default 60), then it's told to stop and sum up
  --cache 1h
      keep the conversation cached for an hour with no call reading it, not 5 minutes (for long pauses between goals: writing it costs more, 2x the input price, not 1.25x; reading it is cheap either way)
  --confirm
      show each piece of code and ask before running it (the model can ask that for one piece: review = true)
  --resume
      carry on with the goal in /claude/resume.txt, in a new conversation, with the options it was given (what autostart runs after a reboot; nothing there: it asks)

When it stops, type the next thing to do (it keeps the conversation), /new to start a new conversation (its memory and files stay, and its helpers are loaded again), or press Enter on an empty line to quit. Ctrl+T stops it (under T.run, so the saved position stays right).

Colour (an advanced computer or turtle): the code it runs is highlighted as vi does it (lib/syntax: keywords yellow, comments green, strings red, numbers and nil/true/false magenta, library names cyan), what the code prints is grey, prompts and questions yellow, retries orange, errors red; Claude's own words are white.

Reading back: when more comes out than the screen holds, it opens in the pager (lib/pager.lua) at the first line you haven't seen before it asks you anything: the mouse wheel, arrows or space to scroll, q to get to the prompt.  At an empty prompt, the wheel up (or PgUp) opens the whole session.

Setup:
  * put an API key in `claude.key` next to this program (`edit claude.key`, paste the key, save).  Make it a key of its own with a spending limit: anything on a computer's disk can be read by whoever can open the turtle or the server's save folder.  The file is in .gitignore, and `git pull` never touches untracked files.
  * the server's CC:Tweaked config must allow HTTP to api.anthropic.com (the same `http.rules` allow-list that lets `git` reach your host).

What it costs: every round trip (one tool call) sends the whole conversation, so a long job is many calls; the conversation is cached (the API's prompt caching), so each call reads what came before from the cache, at a fraction of the price, and pays in full only for what's new.  When a goal ends its tokens are printed: those read from the cache, written to it and new, and what came out.

What's new: claude keeps the ccnix version it last ran with in /claude/.version.  When ccnix has been updated since, the first goal tells the model what changed for it (help/claude-news.txt, from doc/claude-news.txt: the lines for each version since).

Resuming after a reboot: while a goal is under way /claude/resume.txt holds it (a first line of the session's options, then the goal, to which the model adds where it is), and it's removed when the goal ends or Ctrl+T stops claude.  With the settings ccnix.autostart = claude and claude.resume = true, a turtle that went down mid-goal (a server restart, its chunk unloaded) starts `claude --resume` at boot: the model is told it was interrupted and to read its memory and carry on. That spends API money with nobody at the turtle, so it's off unless set; with no goal to resume, autostart starts claude waiting for one.

Keeping the player told: when claude.remindChat minutes (default 15, 0 for never) pass with no chat message to the player (T.report, the chat tool), the model is reminded after the next tool results.

Hearing the player: while claude waits for the model's reply, a chat box aboard goes on the free side (an empty one or a tool's: never the chunk controller's or another upgrade's) and the chat is heard; it stays on while the model's code runs, until the code first digs or attacks (what was there, the pickaxe, goes back on at once and the code carries on), and run_program and the goal's end put it back too.  What turtle.player says (anyone, when it isn't set) comes with the next results, or chatHeard() in the code takes it; the player's other messages while T.report.ask waits come too.  Each lua result says how long its run took, and in a long one how long the chat went unheard. claude.listen = false turns it off.

The log, claude.log beside the program: each entry with its time (UTC); the options a session started with, the goals, the code and what it did, the thinking, each call's tokens and how long it took, retries, clears, and each goal's tokens in all.  A call that writes many tokens to the cache after a long gap is the cache having run out (--cache 1h). At 256 KB (the setting claude.logSize, in bytes) it becomes claude.log.1, the older copies moving up to claude.log.3 (the setting claude.logKeep: that many kept, about 8 hours at 3), and a new claude.log starts.  On a disk with less than a quarter free (turtlelib's map, .map/, counted in) fewer are kept, the oldest going first; the current log always stays.

Its helpers: functions it wants again are kept one to a file, each with keep(name, code) in its code, which runs the code (so it's defined at once) and writes it to /claude/helpers/<name>.lua; code that doesn't compile or run is refused and nothing is written.  At the start of each session /claude/helpers.lua (an older single file, which it can still write) and then each file in /claude/helpers/, in name order, is run in the code's own world, each on its own, so what they define is in scope for every chunk the model runs.  The files that fail are told to the model with its first goal, and the session goes on without them.  A call whose code declares a `local` at its top level (an unindented `local` line) gets a note: that name is gone when the call ends.

What it can call: the system prompt carries turtlelib's index, one line a function (turtle/tl/index.txt, made from the comments above the functions by sim/mkhelp.py), and says where help/turtlelib.txt, the full reference, is to read with fs.  The index is read when claude starts; if it isn't on the computer the prompt says so and sends the model to the source.

The code has the turtle, turtlelib, peripherals, the plain Lua bits, CC's http, `require` for CraftOS's cc.* modules (cc.strings, cc.pretty, ...) and ccnix's libraries for text, the network and the world (text, scan, convert, path, glob, regex, tables, fileio, getopt, net, netdb, httpc, mc), and the files: fs, io, loadfile and dofile read anything but the API key, and write only under /claude/ (so it can't rewrite the programs or the startup).  No shell.

Each result of the code ends with a line saying where the turtle is, its fuel and what the call used, its free slots, and any lava or water beside it (the log has it too; the screen doesn't).

The other tools:
  status
      where it is, fuel, what's around, what it carries, the tools equipped, what's attached, the protected areas near it, a mine job, the network
  run_program
      runs one of ccnix's turtle programs (mine, farm, mow, home), or ip and ping for the network, with arguments, or reads its manual (help/)
  ask_user
      asks you, at the prompt
  chat
      says something in the game's chat (through a chat box, to the setting turtle.player, or everyone when it isn't set), or asks there and waits for an answer starting with "claude" from that player, or one typed at the prompt, whichever comes first (T.report.ask); the wait is kept under the cache's time unless the model asks for longer
  memory
      its notes, kept between sessions in /claude/memories/ (the API's memory tool: view, create, str_replace, insert, delete, rename, only under that folder)
  web_search, web_fetch
      run on Anthropic's side, not the turtle's (each costs a little; at most a few a reply)
Old tool calls (the code and its results) and old thinking are kept while the conversation grows, and cleared in one go once a call's input reaches 180k tokens (the API's context editing): all but the last 6 calls, the memory tool's kept, and the thinking before the turn in progress.  Each clear has the cache written again, so one deep clear pays for many calls.  When the API says the conversation is too long all the same, it's sent again with more of it cleared.  A reply paused partway through its web searches is carried on.

Position: it picks up turtlelib's saved position (.turtlepos) if there is one, so `home` still works afterwards; otherwise here is (0,0,0) facing +z.  In a session T.cfg.maxHeight is 256 (programs keep 16), unless the helpers or the model set it otherwise.
