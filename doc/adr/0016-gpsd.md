# ADR-0016: gpsd: a GPS host as a ccnix service

**Status:** Proposed
**Date:** 2026-11-17
**Deciders:** Dan Theisen

## Context

CC's GPS has two halves:

- **Hosts:** `gps host [x y z]` turns a computer into a host. It sits in
  the foreground until the computer stops.
- **Clients:** `gps.locate()` and `gps locate` on any computer, turtle or
  pocket computer.

On a ccnix computer, `gps host` takes over the shell. Nothing restarts it
if it ends, and nothing logs it.

ccnix already has the machinery a host wants:

- init keeps services running (`service`, `help init`);
- syslogd files what they say;
- `sysctl` holds settings;
- `setup` puts the pieces in place.

The turtle library uses GPS for `T.setOrigin()` (`turtle/tl/world.lua`,
`gpsFix`). A constellation of ccnix hosts would serve it, and every stock
computer, without changing either.

### The protocol (what clients expect)

CC: Tweaked's `gps` API and program define it. That code is under the
CCPL, so ccnix writes its own from the protocol and copies nothing.

- **Channel:** everything is on channel 65534 (`gps.CHANNEL_GPS`).
- **The ping:** a client opens 65534 on its first wireless modem, then
  transmits the string `"PING"` with channel and reply channel both
  65534.
- **The reply:** a host answers on the ping's reply channel, with reply
  channel 65534. The message is `{x, y, z}`, a table of exactly three
  numbers.
- **What the client accepts:** a reply on 65534 with reply channel
  65534, carrying a distance (so wireless; a wired modem gives none),
  with a three-number message.
- **The fix:**
  - A distance of 0 is the answer itself.
  - Otherwise three fixes trilaterate to one or two points, and a fourth
    picks between them.
  - A fix within one block of one already held replaces it.
  - Hosts must not lie in one plane, and four are the least that work
    anywhere.
- **The timeout:** the client waits 2 by default. That is a timer, so
  game ticks. At `/tick rate 60` it is about 0.67 real seconds, but still
  40 game ticks, and replies come back within a tick or two.
- **The stock host:**
  - it refuses on a pocket computer;
  - without coordinates it locates itself first;
  - it answers on the first wireless modem only;
  - it prints a count of requests served.

### ccnix facts that bear on it

- **No channel clash:** the network stack uses channels 60000 up to
  64094, clear of 65533 to 65535 (`lib/net.lua`, `N.CHANNEL`). It closes
  only its own channels, so a service holding 65534 open on the same
  modem is safe.
- **Events reach every service:** init hands each event to every process
  waiting for it (`lib/proc.lua`), so gpsd sees each `modem_message`
  whatever else is listening.
- **Output is logged line by line:** a service's printed lines go to the
  system log, one line each. The stock host's per-request counter would
  flood it.
- **The mod needs nothing:** ccnix-mod has no GPS code. The ROM picks up
  new programs from this repo.

## Decision

Add **gpsd**:

- a program, `bin/gpsd.lua`, run as an init service;
- a help page;
- a `setup gpsd` app;
- a sim.

gpsd answers the stock protocol, so every computer's `gps.locate` uses
it. D1 to D8 below are the choices, each with a recommendation.

## Options considered

### D1. What gpsd is

- **(a) A host only. Recommended.** It answers pings. Programs keep
  calling `gps.locate` as they do now.
- **(b) A host and a position service, like Linux's gpsd.** It would also
  locate the computer it runs on and keep the answer for local programs.
  ccnix computers that run gpsd don't move, and the ones that move
  (turtles, pockets) can't run it (D5). So nothing would use the second
  half.

The name follows the `*d` daemons (syslogd, telnetd, httpd, ircd). It is
not a port of Linux's gpsd.

### D2. Where the host's position comes from

- **(a) Settings, then itself. Recommended.**
  - `gpsd.x`, `gpsd.y` and `gpsd.z` (set with sysctl, or with `setup
    gpsd x y z`) are the position.
  - Without them, a command computer reads its own block position.
  - Any other computer locates itself with GPS, trying every 10 s until
    the other hosts give a fix, then serves.
  - The self-located position isn't saved: a computer picked up and put
    down elsewhere locates again at boot.
- **(b) Settings only:** like `gps host x y z`. A host joining a
  constellation then needs typing it couldn't need.
- **(c) Save the self-located position:** it could start without the
  others, but would serve a stale position once moved (computers keep
  their settings when picked up).

### D3. Checking the configured position

A host with a wrong position (a typo, or a computer moved since) spoils
every locate in its range. The stock host never finds out.

- **(a) Check at start. Recommended.**
  - At start, if the other hosts give a fix, compare it with the
    settings.
  - More than 1.5 blocks off: gpsd doesn't serve. It logs an error naming
    both positions (crit, so it shows on the console) and keeps checking
    every minute.
  - No fix (too few other hosts, or the two points four hosts can't
    separate): it serves.
  - `gpsd.check=false` turns the check off.
- **(b) No check:** as stock.

### D4. Which modems it answers on

- **(a) Every wireless modem. Recommended.**
  - Ender modems count as wireless.
  - It answers on the modem the ping came through.
  - Modems attached later are picked up.
  - Wired modems are left alone: they give clients no distance.
  - The ping's distance is from the modem, so a host with two modems
    gives a client two fixes less than a block apart. The client keeps
    one.
- **(b) The first wireless modem only:** as stock.
- **(c) A setting naming the modem:** more than anyone needs.

### D5. Which computers can run it

- **(a) Computers only. Recommended.** A pocket computer and a turtle
  move, and are refused with the reason. The stock host refuses only the
  pocket computer.
- **(b) Turtles too:** a parked turtle could host, but one moved later
  serves a stale position (D3 catches it only at start).

### D6. What it logs

It logs with lib/log, facility daemon.

- **(a) Starts, problems, and a count now and then. Recommended.**
  - A line when it starts serving: the position, where it came from, and
    the modems.
  - The D3 mismatch.
  - "no wireless modem" while there isn't one.
  - A count of requests served, at most every 10 minutes and only when
    it changed. `service status gpsd` shows the last of these.
- **(b) A line per request:** floods the log. A busy turtle base pings
  every few seconds.

### D7. Setting it up

- **(a) `setup gpsd [x y z]`. Recommended.** It installs gpsd and
  `help gpsd`, plus init (and syslogd, as `setup init` does), and makes
  gpsd a service enabled at boot.
  - With x y z, it sets `gpsd.*`.
  - Without them, it prints that the host will locate itself, and how to
    set a position.
  - `help gpsd` describes a constellation: four or more hosts, not all
    at one height, high up for range, ender modems for range across the
    world.
- **(b) By hand only:** `service add gpsd gpsd`.

### D8. The tick rate

The stock client's 2 s timeout counts game ticks. That is still 40 ticks
at any tick rate, and replies come back within a tick or two.

- **(a) Change nothing. Recommended.** That covers both `T.setOrigin`'s
  `gps.locate(2)` and gpsd's own self-locate. The real-seconds work in
  ADR-0015 D9 was for waits on people and remote machines. Ticks are the
  right clock here.
- **(b) Real seconds** (`realtime.ticks(2)`): it would wait three times
  as long for nothing on a fast server.

## Trade-off analysis

- **The check (D3)** is the only part that goes beyond the stock host.
  It costs one locate at start and every minute while refusing to serve.
  It catches the one mistake GPS users make most, which otherwise shows
  up only as turtles going to the wrong place.
- **Self-locating without saving (D2)** keeps hosts honest when moved.
  The cost: a constellation of only self-located hosts can't start. The
  first four need positions, as in the stock game.

## Consequences

- **Easier:**
  - A GPS constellation runs on ccnix computers beside their other
    services, restarts by itself and logs.
  - A typo in a host's position is caught before it serves.
- **Unchanged:**
  - Clients, stock `gps`, the turtle library and the network stack.
  - ccnix-mod: nothing beyond the ROM picking up the new files with the
    usual lockstep bump.
- **To watch:** whether the per-minute re-check while refusing (D3) is
  noisy. It logs once, then only when the answer changes.
