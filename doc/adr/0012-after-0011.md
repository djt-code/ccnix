# ADR-0012: After ADR-0008 and ADR-0011: building for the player, a chat box that listens, and resuming

**Status:** Accepted (2026-11-16): D1 to D5 as recommended, D3 as
revised below (the chat box listens only while the harness waits for the
model; the chunk controller never moves)
**Date:** 2026-11-15
**Deciders:** Dan Theisen

## Context

ADR-0008 built turtlelib's building library and ADR-0011 (ccnix 0.51.0)
fixed what the in-game model reported after using it for days. The user
asked (2026-11-15) for a review of both ADRs for every item still worth
doing, and a new ADR from them.

**Method.** A read-only reviewer checked sixteen candidates against main
at 0.51.0: ADR-0008's "not done" items and Consequences, everything
ADR-0011 put off, and the in-game report section by section. It cited
the code for each gap and the field notes and log for its value. The
claims this ADR rests on were spot-checked in the code.

**Two findings change the picture.**

- **The route search is fast.** In the field log an 80,000-cell A* search
  took about 4 s and a 20,000-cell one about 1 s. The "gave up" failures
  were goals walled in (by doors and protected areas, which 0.51 now
  names and lets through known air), not slow searches. Bidirectional
  search or a faster planner isn't needed.
- **Sign text works.** `turtle.place(text)` writes a sign's text in game
  (the model did it twice); turtlelib's wrapped `place` passes the text
  through. What's missing is placeAt knowing signs.

**What is still open and has field value**, most first:

1. **Building for a two-tall player.** The player corrected the model's
   stairs, headroom and railings in six tasks (10, 11, 23, 28, 29, 31).
   0.51 put the rules in the prompt; nothing checks a build against them.
2. **Placing with support.** A top slab under each stair is the player's
   style; the model placed them by hand three times (dig below, stand,
   place up, restore the floor). The ladder rows in tl.place are empty
   (`down = {}, up = {}`, place.lua:157), though the model placed ladders
   from above and below in game, as the build mock's model predicts.
   Blueprints have no "this cell after that one" order.
3. **Chat while working.** The chat box is attached only while
   `T.report.ask` waits (journal.lua:290); what the player says while the
   turtle works is never heard, and the turtle API's own event pulls drop
   chat events. The one free side is juggled by hand between the
   pickaxe, modem, chat box, scanner and crafting table (four times in
   the notes); digs fail when the pickaxe is in the inventory.
4. **Interruptions.** A server restart, a chunk unload and a full disk
   each ended a session; claude can't start again by itself (autostart
   knows mine, farm, mow and autocompost only, autostart.lua:37), and the
   conversation lives only in memory. The 256 KB log held 2 h 41 min.
5. **Small ones.** Sign text; routes with `dig = true` would dig the
   player's ladders, trapdoors, signs, lanterns and torches outside
   protected areas (the default avoid list is lava, fire and `*_door`,
   turtlelib.lua:1429, and `*_door` misses trapdoors); harvest's "no free
   cell beside it" doesn't say `opts.move = {dig = ...}` tunnels in; a
   walled-in goal costs the whole search limit; a re-zero leaves `.build`,
   `.undo` and `mine.job` in the old frame (ADR-0008 18a), which ADR-0011
   found as a stale "active" mine job.

**Not worth doing now** (evidence against, or waiting for the next field
report): scouting and a loot table (three blind trips found nothing;
asking the player worked); a persistent `T.cfg` (helpers kept with
`keep()` already do it per session, and a turtle-wide one would change
farm's `maxHeight`); a harness-side trimmer (0.51's server-side clearing
is unmeasured until the next log); no-entry areas (no need seen); a
liquid-shell protection (superseded by ADR-0011's guard); review by chat
(never used).

## Decision

1. A lint for player access, run by `T.verify` and at the end of
   `T.build`, then a walkability search (D1).
2. Placing with support: ladder rows, order hints in blueprints, and a
   support strategy for top slabs (D2).
3. In a claude session, a chat listener while the model thinks (D3).
4. claude resumes an interrupted goal after a reboot, when set to (D4).
5. The log keeps more history (D5).
6. Without a decision (Phase 1): sign text, a furnishings avoid list,
   harvest's hint, a fast fail for a walled-in goal, the frame stamped
   on saved jobs, and a prompt line on keeping settings with `keep()`.

## Options considered

### D1. Checking a build for the player

| | A: the prompt only (as now) | B: a lint, then `T.walkable` | C: a full walkability search first |
|---|---|---|---|
| What | the rules in the system prompt | `T.lint(box or plan)`: 3 air above each stair's walking line, a free approach and exit for each flight, railings meeting only on a diagonal, drops over 3 with no rail, a lantern at head height over a walk cell; `T.verify{player = true}` and the end of `T.build` report its warnings. Then `T.walkable(from, to)` for a 1x2 body | the search first, the lint from it |
| Lines | 0 | ~100, then ~150 | ~250 at once |
| Verification | none | a new turtlelib_walkable on the build mock (stairs and slabs need inspected states; a scan has none) | same |
| Blast radius | | warnings only: a build never refuses | |

**B.** The lint catches every mistake the player reported, from the map
alone, and is read-only. Warnings, never refusals: the player's own
designs may break a rule on purpose.

### D2. Placing what needs support

| | A: as now | B: rows and order, adding only | C: B, and dig below |
|---|---|---|---|
| What | placeAt fails with its reasons | ladder rows from above and below; a blueprint order hint (`after = {x,y,z}`, and stairs before the top slab under them by default); for a top slab with nothing above: place a temporary block above, then the slab, then take the block away | also the model's own trick: dig the floor below, stand in it, place up, restore the floor with the same block (`opts.digBelow`) |
| Lines | 0 | ~5 + ~30 + ~60 | +~40 |
| Verification | | turtlelib_place and turtlelib_blueprint on the build mock | same |
| Blast radius | | a temporary block appears for a moment | the player's floor is dug and put back |

**B by default, C's dig-below when a job asks** (`opts.digBelow = true`).
Adding a block and taking it away touches nothing of the player's; digging
their floor does, so it's asked for.

### D3. A chat box that listens

| | A: as now | B: resident in claude sessions | B': listen while the model thinks | C: B for every program |
|---|---|---|---|---|
| What | the chat box is equipped only to speak or wait | the free side's resting item is the chat box; every dig swaps the pickaxe in and back | while the harness waits for the model's reply, the chat box goes on the free side and chat is heard; before the model's code runs, the side's previous item goes back; what was heard is added to the next result ("player said ... at t") | the same for mine, farm and mow |
| Lines | 0 | ~40 turtlelib, ~40 claude.lua | ~30 turtlelib, ~40 claude.lua | more, and their sims change |
| Verification | | | claude_drive with a mock chat box and chat events during a request | |
| Blast radius | | a swap per dig | two swaps per step | every program's equipment |

**B' (accepted).** Chat is now the model's main channel to the player,
and replies that arrive while it works are lost today. The wait for the
model is most of a step's time (10 to 60 s at the field's context sizes),
so listening then hears most of it, at two swaps a step instead of one
per dig. Chat said while the model's code runs is still missed: the chat
box keeps no history.

**The chunk controller never moves.** An unattended turtle needs its
chunk loaded, so the side holding the Chunk Controller (or any non-tool
upgrade) is never used for the swap; turtlelib's equip already parks
only tools. If neither side is free of non-tool upgrades the listener
stays off and the session's first result says why. The field showed the
failure this rules out: an early note swapped the geo scanner into the
controller's side.

### D4. Resuming after a reboot

| | A: as now | B: opt-in resume | C: always |
|---|---|---|---|
| What | a reboot ends the session | `ccnix.autostart = claude` (autostart's own setting) and `claude.resume = true`: the model keeps `/claude/resume.txt` (the goal and where it is); at boot claude starts a new conversation with "you were interrupted; read your memory and resume" and the file's goal, with the usual step cap | any boot with a resume file starts claude |
| Lines | 0 | ~60 | ~50 |
| Verification | | claude_drive and autostart_boot | |
| Blast radius | | spends API money without anyone at the turtle, only when set | the same, unasked |

**B.** A session that resumes itself is what the field needed three times,
but it spends money unattended, so the user turns it on.

### D5. How much log to keep

**`claude.logKeep`, default 3 files of 256 KB (about 8 hours at the field
rate), capped so the log and the map together leave a quarter of the
disk free.** Today 2 h 41 min is all a review can read. Thinking stays in
the log (it's the most useful part for a review).

## Trade-off analysis

The pass spends its effort where the player's corrections were: the lint
and the support strategies, both read-only or additive. It declines the
work the field showed doesn't pay (scouting) or can't be judged yet (a
trimmer, named routes: 0.51 may have fixed the entry problem by letting
routes through protected air). The one default that changes behaviour
without a decision is the furnishings avoid list: routes with
`dig = true` stop digging ladders, trapdoors, signs, lanterns, torches and
rails, which only ever protects the player's things.

## Consequences

- Builds come back with the player's view of them; the model fixes a
  missing railing before the player walks into it.
- The chat box is on the turtle while the model thinks; the pickaxe is
  back before its code runs; the chunk controller never moves.
- With D4 on, a server restart costs a few minutes, not the session.
- **The next field report (v3) should say:** whether 0.51's routes get
  into enclosed buildings (if not: named routes and entry points);
  tokens per call (if still 300k: the trimmer); whether the lint's
  warnings match what the player would have said.

### As built (ccnix 0.52.0, #33 to #36)

- The blueprint hint is relative to each cell of its legend entry
  (`t = oak_slab[type=top] after 0,1,0`), so it survives `opts.at` and
  covers a flight in one line.
- `T.walkable` is a search of its own, not tl.path's A* (that one is tied
  to the turtle's six moves and its cell classes).
- A resumed session uses the interrupted one's options (its `--steps` and
  `--cache`), kept on resume.txt's first line.
- The frame is a number in the data file `.frame`, one more at each
  re-zero that moves 0,0,0; files from before it carry on as before.
- Hanging signs are left as plain blocks; the 15-character sign line is
  CC's, to be checked in game.
